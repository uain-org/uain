# Advisory estimates in project task briefs

**Status: held proposal; documentation only. Do not merge or activate until the open wording and acceptance requirements are resolved.**

Status: recovered draft; not active runtime behavior.

This preserves unfinished guidance for the project CEO and manager prompts. The
current implementation is [leadership.mjs](../../services/project-organizations/src/leadership.mjs).
The existing effort/difficulty price rationale is the proposed place for a brief,
rough estimate, with uncertainty when needed. It would remain advisory and would
not decide publication, acceptance, verification, funding or payment.

The intended division of responsibility is unchanged: the CEO and manager are
responsible for clear, useful task briefs that appear reasonably doable. The
system accepting a task discovers and chooses its tools and approach within
existing access, safety and budget rules. This gives neither side new authority.

## Reconciliation still required

The older draft rejected deep feasibility analysis, numeric scoring, difficulty
thresholds and fixed completion-time targets. The current manager contract also
requires self-contained, concrete briefs and suggests tasks of about an hour.
This document does not decide that conflict or replace the current prompts.
Any implementation must retain the self-contained acceptance criteria, existing
pricing fields, output schema and authority fences.

The original draft had no controlled live-model acceptance. Wording compatible
with the current task contract and that acceptance remain open before activation.
No model call, prompt replacement, task creation or release is performed here.

The retired holder/browser review implementation is not restored. Existing launch,
wording, payment-exit and financial/operational holds are unaffected. This proposal
is not evidence of earnings, funded task availability or deployment.
