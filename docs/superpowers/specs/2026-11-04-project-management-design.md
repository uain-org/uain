# AI project operations and feedback repair

Rahul requests fixes from #uain's 4 November feedback PDF, at least 50 active projects, ultimately management of all proposals, and AI-managed accountability, funding/access/evidence/meeting decisions. He explicitly asks us to assume answers and create the systems; implementation proceeds without another product-question round.

Extend the established Node/React BAINK stack and preserve the private Paperclip runtime. A separate bounded SQLite operations journal owns catalogue management, distinct from immutable source proposals, native admission and settlement. Every validated proposal can receive a stable coordinator/reviewer role and initial intake tasks. At least 50 are prioritized for real model-authored project-specific plans. Active means a current substantive management plan and running coordination cycle, not scientific acceptance, funded work, paid rewards or independently operating model processes. Show both source and operational state. Unprocessed projects remain queued. No fabricated novelty searches or evidence.

The existing Mac Claude CLI supplies bounded plan generation; credentials remain local. An explicit operator ingestion file feeds the server. A resumable worker can repeat through all proposals with concurrency one and a per-run cap. Coordination performs evidence readiness, idempotent signed user chat, task/evidence guidance and review separation. AI-generated review is not independent scientific acceptance. Missing original material is tracked as missing. Public profiles require signed ownership and exact authorized scopes; meeting access stays private by default. Funding decisions can be proposed, never minted or self-approved by this new manager. No native financial-policy activation or private keys are introduced.

Use existing immutable BAINK deployment and rollback guards; add read-only capability exposure. Preserve unrelated dirty files and state. UI design goes to actual Claude Opus 5.5. Session persistence uses nonextractable browser CryptoKeys in IndexedDB with explicit user choice and logout deletion, never plaintext private keys in browser storage. Native installation evidence must retain independent verification; expose only verified material and truthful platform limitations.

Alternatives: enable the private Paperclip fleet directly (unqualified providers and scoped write permissions make this premature); merely relabel inactive rows (does not meet the request); extend the existing BAINK runtime with a durable management journal and bounded model worker (selected implementation judgment). Model and scientific authority remain separate.
